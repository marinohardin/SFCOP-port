## How the names CSV was made

`directplay_names.csv` was written by hand, by the P1-7 work package agent (an AI coding agent), not
generated by a script. Its inputs were:
- the `run.sh` dump in `work/directplay/dump/`: `functions.tsv`, `vcalls.tsv`, `vtables.tsv`,
  `eh.tsv` and the decompiled C;
- byte reads of the exe for the EH and RTTI records.

The `evidence` column gives the basis for every name. It says "inferred" when the name rests on
behaviour rather than on a string, RTTI or EH record. A rerun of `run.sh` refreshes the tables, not
the CSV.

**Import:** every row is meant to replace the program's current name at that address. That includes
the rows whose evidence says "Ghidra calls it …" (0x00431EEA, 0x0043405F, 0x00434195 and
`_purecall` at 0x00737F86), where class recovery picked the wrong class. The two return-0 stubs at
wrapper slots 29 and 37 (0x00611980, 0x006123A0) are shared with other classes' vtables. They are
left out on purpose, so they keep their current names (see `directplay.md`, "The wrapper's
interface").

## Reproduce

Needs Ghidra 12.2 and the shared program export at `work/ghidra/StarFleetOP_2552.gzf` (see
`ghidra/README.md`, P1-1). One command, from the repository root:

```bash
analysis/netcode/ghidra/run.sh
```

It imports the export into a private project under `work/directplay/` (once) and runs the scripts
with `-readOnly`, so neither the shared project nor the private copy is changed. It takes about two to
four minutes with a 6 GB heap and four cores. Raw output (all TSVs and the decompiled pseudocode) is
written to `work/directplay/dump/`; only the address tables above are copied into `results/`.
Override `GHIDRA_HOME`, `SHARED` or `WORK` in the environment to use other locations.
