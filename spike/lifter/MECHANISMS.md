# Lifter mechanisms: what pcrecomp, RA2, NFSU2Recomp actually do

Read-only study of the local clones under `work/lifter/`. Nothing was built or run from them. Paths are relative to each clone.
Abbreviations: **PCR** = pcrecomp, **RA2** = redalert2-recomp, **NFR** = NFSU2Recomp (arm64 macOS fork, own Python lifter), **NFC** = nfsu2-recompiled (PCR fork: Windows x86 + Android arm64).
"Code" means I read the source; "claims" means README/docs only.

## 1. Workflow and the 32-bit guest on a 64-bit host

**PCR/RA2 order** (RA2 `docs/building.md` "Step by step", `run_lift.py`; same on macOS via `setup.sh`):
`tools/pe/pe_analyze.py --json` -> `tools/cpp/rtti.py -o rtti.json --seeds rtti_seeds.json` -> `tools/disasm/disasm32.py --seed-functions rtti_seeds.json -o functions.json` (about 15 min for 4 MB of code) -> per-game `run_lift.py --all` (imports `generate.py`: `true_extent`, `find_splits`, `linear_disassemble_function`, `lift_function_linear`, plus `lift32.Lifter(precise_carry=True, precise_sbb=True)`; RA2 `run_lift.py:653-780`) -> writes `recomp_*.c` chunks of 400 functions, `recomp_funcs.h`, `recomp_dispatch.c` (sorted `{va, fn}` table) -> `name_lift.py` (names only) -> `build-macos.sh` (CMake+Ninja, clang `-O2 -fno-strict-aliasing -fwrapv`, `RA2 CMakeLists.txt:48-100`) links lifted C + `pcrecomp/runtime/win32hle/*.c` + a small host. `tools/lift/recover.py` and `disasm/seed_from_log.py` feed back functions found only at run time. Hooks and remaster patches are injected as C after a given instruction VA (`apply_patches :466`, `HOOKS :72`). `generate.py main()` (`:941`) is a bare older driver that does none of the seeding; real projects write their own `run_lift.py`.

**NFR order** (README "How it works", `tools/`): `reloc2.py` (recover the relocation table hidden in an extra section) -> `genall.py` (recursive descent seeded by relocs, calls `lift.py`, 128 shards + `fntab.c`) -> `build.sh` (clang -O3) -> `link.sh`. Discovery leans on relocs; StarFleetOP.exe has none (see section 8).

**Guest memory model.** All three keep the image at its guest VA *inside* a 4 GB host reservation; none maps it at 0x400000 in the host.
- PCR `recomp_types.h:177-188`: three `ADDR(va)` variants: flat (`va` is the host address, 32-bit hosts only), `RECOMP_MEM_BASE` (`(uint32)va + constant`), or `+ g_mem_base`. `MEM8/16/32/F/D` are `volatile` loads through `ADDR`.
- `win32hle/guest_mem.c:155-181`: `mmap(want, 4 GB, PROT_NONE, MAP_NORESERVE)`; reservations are `mmap(MAP_FIXED)` inside it in 64 KB units (host pages are 16 KB on Apple silicon, `:10-13`). Page zero stays unmapped so guest NULL faults. The PE is mapped at its own base through `hle_vm_reserve` (`pe_loader.c`).
- **RA2 on macOS**: `CMakeLists.txt:76-85` fixes `RA2_MEM_BASE=0x100000000000ull` (16 TB up, "free on arm64 and x86-64 alike") so the lift adds a compile-time constant. README says macOS arm64 passes its 30/30 playtest suite for both games (claim; the suite is in `tools/playtest.py`).
- **NFR on macOS**: `runtime/mem.c:35-39`, `cpu.h:7-26`: `mmap(0, 4 GB, PROT_NONE)`, `mem_commit` = `mprotect` in 16 KB pages, `MR32(a) = *(uint32*)(g_mem + (uint32)a)`, which compiles to `ldr w, [xbase, waddr, uxtw]`. `PROJECT.md:66-70` records that mapping the guest at 0x400000 with `__PAGEZERO` shrunk to 0x4000 gets the process SIGKILLed on arm64 macOS. So base+offset is the only workable scheme there.
- **Host pointers back to the guest**: strict. `win32hle.h:41-57`: anything the guest is handed must live in guest memory (`hle_alloc`, `hle_vm_reserve`, `hle_scratch`); `hle_va(p)` of a pointer outside the block is `hle_fatal` ("host pointer handed to the guest", `guest_mem.c:150`). `RETP()` wraps this. NFR does the same by construction: its heap (`gheap.c`, GH_BASE 0x10000000) and COM objects live in `g_mem`.
- Guest stack and TIB are guest memory; host recursion mirrors guest calls (each lifted call is a C call that also pushes a dummy return address on the guest stack, `RECOMP_CALL` `:1157`).

## 2. C++ exceptions, SEH, fs:

| Aspect | What the code does |
|---|---|
| fs:/gs: operand | `lift32.py:423-429` emits `FS_BASE + (addr)`; `g_fs_base` is a per-thread simulated TIB in guest memory (`host_lite.c:120-128`). NFR: `c->fs_base` (`lift.py:386-390`); segment *writes* are dropped (`:425`). |
| TIB contents (win32hle) | only `[0]=-1`, `[4]` stack base, `[8]` limit, `[0x18]` self. **No `fs:[0x2C]` (TLS array), no `fs:[0x30]` (PEB)**; `pe_loader.c` has no TLS-directory handling (grep). |
| fs:[0] chain | Prologues that install `{next, handler}` records are lifted literally, so the SEH chain is ordinary guest data. Nothing walks it unless a throw does. |
| `eh32.c` (PCR `runtime/native32/eh32.c`) | `_CxxThrowException` shim reads ThrowInfo, walks the guest `fs:[0]` chain, decodes `mov eax,FuncInfo; jmp __CxxFrameHandler` stubs (`:84-92`), matches catch types by decorated name (`catchable :127`), runs unwind-map funclets and the catch funclet as guest code (`call_funclet :96`), then `longjmp`s to a setjmp landing pad in the owning lifted function (`:195-211`). |
| lifter side | `tools/lift/eh32.py resume_points` finds a function's catch-resume addresses from FuncInfo (needs `push ebp; mov ebp,esp` within 12 insns, `:79-84`); `generate.lift_function_linear(eh_resume=...)` adds `RECOMP_EH_ENTER()` (`recomp_types.h:1257`, setjmp) and labels. **No driver in PCR or RA2 calls `resume_points`**; the project that does (Unreal Tournament) is not local. |
| Not supported | `__try/__except` / `_except_handler3` frames are skipped, `__finally` does not run (`eh32.c:36-39`). `call __EH_prolog` functions get no landing pad (inference from the prologue test). Throws with no catching guest frame go to the real host `_CxxThrowException`. |
| **Where it works** | `eh32.c` includes `windows.h`, uses `IsBadReadPtr`, `__declspec(thread)`, `GetProcAddress`, and is registered only in `native32.c:856` as an *import named* `_CxxThrowException` of a dynamically linked msvcrt. native32 is MSVC-x86-only inline asm (`native32.h:25`). **It is not part of win32hle**, so it does not exist on macOS today. |
| win32hle | `RaiseException` just prints "guest exceptions are not handled" and ends the run (`kernel32_crt.c:482`); README "Not here: guest SEH and C++ exceptions". |
| Did RA2 need it? | No. RA2 repo has no exception handling code or docs (grep for throw/catch/CxxFrame/eh32: nothing relevant). |
| NFR / NFC | NFR: SEH not implemented, `RtlUnwind`/`RaiseException` stubs (`README.md:49`, `win32.c:542`). NFC: "C++ exceptions thrown by guest code reach the native RaiseException ... Not hit yet" (`docs/STATUS.md:92`). |

## 3. __thiscall and virtual dispatch

`ecx` is just the global/local `ecx` register. `call [eax+N]` / `call reg` lift to `RECOMP_ICALL(MEM32(eax+N))` (`lift32.py:1514-1522`); direct calls to catalogued functions are `RECOMP_CALL(sub_xxxxxxxx)`, direct calls to uncatalogued targets degrade to `RECOMP_ICALL` (`:1506`). `RECOMP_ICALL` (`recomp_types.h:1168-1193`): `recomp_lookup_manual` -> `recomp_lookup` (**binary search** over the sorted generated `recomp_dispatch_table`, `host_lite.c:193-200`) -> `recomp_lookup_import` (shim VAs 0x7F000000+16*i, `host_lite.c:248`). **Unknown target**: prints `ICALL: unresolved VA ... from ...`, sets `eax=0`, nothing popped, and execution continues (`:1190`). `ITAIL` just prints. So an unresolved virtual call silently returns 0 and corrupts state later (RA2 `run_lift.py:60-66` says exactly this). In-function `switch`/jump tables become a local `switch` of `goto`s, with fallback to `ITAIL` (`lift32.py:2296-2309`).
Vtables in `.rdata` are untouched guest data; their entries must be *dispatchable*, so every RTTI vtable slot is injected as a function entry (RA2 `run_lift.py:616-632`; MSVC vtordisp thunks are reachable only that way). NFR: `dispatch.c`, a direct-indexed `uint32` table the size of `.text` (14 MB, O(1)); unresolved targets print a one-shot report with 96 bytes at the target, backtrace, and swallow the call (`:95-120`). NFR also has a run-time x86 interpreter (`genexec.c`) for code the game writes to the stack; PCR's native32 has `native32_add_generated`.

## 4. RTTI

Used for **function discovery and naming only**. `rtti.py` finds TypeDescriptors/COLs, walks vtables, emits `rtti.json` plus `--seeds` for `disasm32.py` (`rtti.py` docstring; RA2 954 classes, 6,665 virtual methods). `vtable_scan.py` does the same structurally as runs of >=3 code pointers when RTTI is off. `name_lift.py` renames lifted C (`UnitClass__virtual_42`, constructors/destructors by vtable stores, debug-string names) and writes a header comment per function. There is **no runtime RTTI code in PCR**: `dynamic_cast`/`typeid` work only because the statically linked CRT's `__RTDynamicCast` is lifted like any function and reads RTTI structures that sit in guest memory at their original VAs (my reading; grep for dynamic_cast/typeid in PCR finds nothing). A failing cast throws `bad_cast` through `_CxxThrowException` (section 2).

## 5. x87

| Item | Code |
|---|---|
| Stack | PCR: **`double g_st[8]`** (global, shared across calls so `st0` returns work), `g_fp_top`, `g_fpu_cw` (`recomp_types.h:57-60, 989-1040`) plus a **`g_st_i64[8]` shadow** so `fild/fistp qword` round-trips 64-bit ints exactly. NFR: `double st[8]` in `CPU` (`cpu.h:42-45`). **Neither uses `long double`** (grep: no `long double` in any runtime or lifter). So no 80-bit anywhere; Apple arm64 limits are moot. |
| 80-bit memory | `fld/fstp tbyte` convert to/from double (PCR `fp_ld80/fp_st80 :1042-1062`; NFR `f80_load/f80_store cpu.h:347-375`, denormals flushed). `fsave/frstor/fnstenv/fldenv` are no-ops or unimplemented in PCR (`lift32.py:1979`, `fcmov*` unlifted in PCR, present in NFR). |
| Rounding mode | `fldcw` stores the word; `fistp/fist/frndint` use `fp_round_cw`/`x87_round` on RC bits 10-11 (nearest-even, floor, ceil, trunc; `recomp_types.h:1023`, `cpu.h:267`). VC6 `_ftol` is CRT code that does `fldcw; fistp; fldcw`, so it works when lifted. PCR's `_ftol`/`_CIsin`... shims (`x87crt.c`) exist only for a dynamically linked msvcrt. |
| **Precision control** | **Ignored by both** (no use of CW bits 8-9). All arithmetic is IEEE double (53-bit). `finit` does not reset `g_fpu_cw` in PCR (`lift32.py:2145`). RA2 argues 53-bit doubles equal what its x87 computes (comment above `CLIP_LINE_SITES`, `run_lift.py:~432`, i.e. default Windows PC=53; the line number is approximate). Anything the original ran at 24-bit PC would differ; neither project models that. |
| Compare | `fcom*` -> `_fpu_cmp` in {-1,0,1,2}; `fnstsw` builds C0/C2/C3 from it; `sahf/test ah` then read the status word (`lift32.py:1791-1830`); `fcomi*` go to EFLAGS via `SSE_COMI`. NaN = unordered (0x4500). NFR keeps real `fsw` with TOP and `fsw_get` (`cpu.h:150-191`). |
| NFR on arm64 | `x87_r1/x87_r2` repair NaN sign/payload to match x86 "real indefinite" and quiet-NaN rules (`cpu.h:277-328`); out-of-range -> integer indefinite (`:331-342`). Transcendentals use libm (`sin`, `pow`...), so results differ in the last bits from a real x87; NFR's own fuzzer skips memory comparison for them (`fuzzisa.py:42, 155`). `f2xm1 = exp2(x)-1`, `fscale` via `ldexp`, `fprem` = `fmod` (full reduction, C2 forced 0), `fprem1` = `remainder`. PCR's `fprem1` is also plain `fmod`, and PCR's `f2xm1` is `pow(2,x)-1`. |
| Caveat | Both x87 stacks hold values at double precision between ops, so sequences relying on 64-bit intermediates (and `fld tbyte` constants beyond 53 bits) differ. Docs say so (`NFR README.md:51`). |

## 6. Lifter coverage limits

PCR `lift32.py`: no TODO/raise list. The fall-through `else:` at `:2181-2183` emits `; /* UNIMPLEMENTED: mnemonic ops */` -- **a silent no-op in the generated C**, no run-time trap and no counter in PCR or RA2 (`run_lift.py` counts only Python exceptions, wrapped into `/* ERROR */ void f(void){}` stubs, `:694`). RA2's "0 errors" therefore does not mean "0 unimplemented"; you must grep `recomp_*.c` for `UNIMPLEMENTED`. `lift32_sse.py` covers scalar/packed float SSE and part of SSE2 integer; the rest of packed SSE2 integer stays UNIMPLEMENTED (`:15-26`). Other gaps seen: `fcmov*`, `fnstenv/fldenv/fxsave`, `fbld/fbstp` not lifted. `CMP_O/CMP_P` are TODO macros (`recomp_types.h:350,352`) but the lazy-flag `recomp_cond` computes OF/PF properly. `difftest.py` (Unicorn) is the verifier.
NFR: unsupported instructions emit `unsupported_insn(c, addr, mn)` which counts and records the first 64 (`dispatch.c:145`); `liftall.py`, `lift_profile.py` report totals (about 310 left, 400 static traps per PROJECT.md header). It also has a flag-liveness pass, `X87OPT` block-level x87 register allocation, and a fuzzer against real x86 under Rosetta (`fuzzisa.py`), the best verification story of the four.

## 7. Imports, COM, DirectX

**ABI (win32hle).** An import is a `void(void)` function that runs *inside the lifted model*: on entry `g_esp -> [ret][arg0][arg1]...`, it reads `A32(i)/APTR(i)/ASTR(i)`, returns with `RET(eax, argc)` which pops `4+4*argc` (stdcall; cdecl/thiscall shims pop what they need) (`win32hle.h:61-72`, README "shim ABI"). The PE loader writes synthetic VAs (0x7F000000+16*i) into the IAT by name or ordinal; `call [iat]` goes `ICALL -> recomp_lookup_import -> shim_entry` (`host_lite.c:248-262`). Unbound imports in a permissive bind become stubs that name themselves and abort (`hle_resolve_or_stub :274`). Native -> guest callbacks (WndProc, thread start, timers) use `hle_call_guest` (`:287`); a global machine lock serialises the register file; loops yield the machine every 65,536 back-edges (`recomp_types.h:1277`).
NFR: IAT slots hold `0xF0000000+index`; `dispatch_indirect` splits on address range: `>=0xF0000000` -> `win32_call` by *name* (string compare chain, `win32.c:300`), `0xE0000000-0xEFFFFFFF` -> `com_call` (`dispatch.c:69-72`).

**COM.** A COM object is guest memory whose first dword is a vtable of shim VAs (`ole32.c:53-70`, `hle_com_vtable`, `hle_com_new`). Guest `call [eax+0Ch]` therefore hits C. NFR encodes `0xE0000000|(iface<<16)|method` per slot (`com.c:2`) and dispatches by pair.

**What win32hle implements (code):**
- `ddraw.c`: `DirectDrawCreate`, `DirectDrawEnumerateA`; interfaces `IDirectDraw`, `2`, `4`; `IDirectDrawSurface` 1-4, Palette, Clipper (software; `DDSURFACEDESC2` via IDirectDraw4). **No `DirectDrawCreateEx`, no `IDirectDraw7` / `IDirectDrawSurface7`.**
- `d3d.c` (833 lines): `IDirect3D3`, `IDirect3DDevice3`, `Viewport3`, `Texture2`, `Material3`, `Light`, `VertexBuffer` (DX6). One HAL device, software rasteriser (`d3d_raster.c`), no lighting, no multitexture; `DrawPrimitiveStrided` unsupported. **No `IDirect3D7` / `IDirect3DDevice7` (no state blocks, no `DrawPrimitive` with DX7 signatures).**
- `dsound.c`: `IDirectSound` (11 methods) and `IDirectSoundBuffer` (21), SDL2 mixer. README says "DirectSound 1".
- `mss.c` (269 lines): only the slice of `mss32.dll` that Civ III's own audio DLL called: `AIL_startup/shutdown/mem_alloc_lock/file_*`, `RIB_find_file_provider`, `RIB_request_interface`, `ASI_stream_*` (MP3 via ffmpeg). It is **not** an `AIL_*` sample/stream/3D-audio implementation.
- No `dinput`, no DirectPlay. `winmm` (timers, waveOut, MCI), `wsock32` (Winsock 1.1 on BSD sockets), registry, GDI text/DIB are present.

## 8. Facts about StarFleetOP.exe that matter (my own byte scan of the retail exe, not tool output)

Static CRT (no msvcrt/MSVCP import); imports DDRAW (`DirectDrawCreate`, `DirectDrawCreateClipper`), DINPUT (`DirectInputCreateA`), DSOUND, WINMM, WSOCK32, mss32, ole32, DBGHELP, comdlg32. Image base 0x400000, `RELOCS_STRIPPED`, empty reloc directory. `.tls` section with an 8-byte TLS block and an empty callback array, and one `mov eax, fs:[2Ch]` in `.text`. (Script-produced counts are in REPORT.md and results/eh_census.json; these were a first heuristic pass.) About 1,120 `mov eax, fs:[0]` / `mov fs:[0], esp` EH-frame installs; 5,524 plausible FuncInfo tables (magic 0x19930520, VC6), of which **127 functions have catch blocks (148 try blocks)**; 7 hits for the constant 0xE06D7363; 2,096 RTTI TypeDescriptors.

## Implications for StarFleetOP.exe

1. **Use PCR+win32hle as the base, with RA2's flow and its fixed `RECOMP_MEM_BASE` on macOS.** Guest = 4 GB `mmap` reservation, base+offset addressing; do not try to map at 0x400000 (NFR hit SIGKILL). Host pointers must never reach the guest; copy that discipline into every HLE shim (D3D/DDraw/DInput).
2. **EH is the biggest gap.** The binary has a static CRT, VC6 `/GX` frames in ~1,100 functions and 127 catch-bearing functions. Lifting the `fs:[0]` frames is free, but `eh32.c` is Windows-only, import-name-keyed, and no PCR/RA2 driver calls `resume_points`. First measure whether the game ever throws (xref the CRT's `_CxxThrowException`/`RaiseException(0xE06D7363)`). If yes: port `eh32.c` to POSIX (replace `IsBadReadPtr`, `__declspec(thread)`), hook the lifted `_CxxThrowException` by address (or intercept `RaiseException` with code 0xE06D7363 in a win32hle shim, since the CRT is lifted, not imported), call `eh32.resume_points` in our own driver. Expect to extend it for `__try/__except` if any exist.
3. **Superseded by the census (REPORT.md): the game is DirectX 6, not 7.** It references IID_IDirectDraw4, IID_IDirectDrawSurface4 and IID_IDirect3D3 and none of the DX7 IIDs, and imports DirectDrawCreate (not DirectDrawCreateEx), which is exactly the surface win32hle's ddraw.c/d3d.c implement in software. A GPU (Metal/SDL) backend for those interfaces is still worth planning; NFR's `com.c`/`metal.m` is the closest arm64 precedent. Still missing: `DirectInputCreateA` HLE, DirectSound3D buffer/listener, and a real `mss32` `AIL_*` sample layer (`mss.c` is a Civ III-shaped stub).
4. **Add TLS and TIB fields.** win32hle's TIB lacks `fs:[0x2C]`; the exe has a `.tls` block and a `mov eax, fs:[2Ch]`. `pe_loader.c` ignores the TLS directory. Needs a small addition (TLS block per thread, pointer at TIB+0x2C).
5. **x87 will be doubles, rounding mode honoured, precision control ignored.** Fine for rendering, risky for the replay oracle and later lockstep netplay if the original game ran at 24-bit PC (DirectDraw/D3D7-era cooperative-level flags can switch it) or relies on 80-bit intermediates. Check whether the retail run sets single precision (look for `fldcw` values and `DDSCL_FPUSETUP/FPUPRESERVE`) and, if so, add per-op `(float)` rounding when `g_fpu_cw` bits 8-9 are 0 (neither project does). Treat transcendental results as approximate (libm vs x87).
6. **Make the lifter loud.** `UNIMPLEMENTED` is a silent no-op in PCR. Add a post-lift grep gate and, ideally, a trap macro like NFR's `unsupported_insn`, so "0 errors" means something. Add `fnstenv/fldenv/fcmov/fxsave` and unknown SSE2 only if the census finds them.
7. **Discovery must be RTTI/vtable-driven, not reloc-driven.** The exe has no relocations (NFR's best trick is unavailable), but 2,096 RTTI descriptors make `rtti.py` -> `disasm32 --seed-functions` -> `run_lift` (inject every vtable slot) the right path; budget about 15 minutes for catalogue, and expect an `ICALL: unresolved VA` loop with `seed_from_log.py` for hand-written dispatch. Unresolved virtual calls return 0 silently; set a strict mode (NFC patch 0003 `RECOMP_STRICT_ICALL`) that aborts.
8. **Verification.** Reuse NFR's approach (flag liveness plus differential fuzzing against real x86 under Rosetta, `tools/fuzzisa.py`) and PCR `difftest.py` (Unicorn); RA2's `--original` oracle runs the shipping code on Windows only, so our replay oracle must come from elsewhere.
